# Nose Calibration

Windows practice-assessment collector, currently a development preview. The collector is a .NET 8 WinForms host with a local WebView2 interface. The web interface contains multiple choice, fill-in-the-blank, dropdown, and two JavaScript coding questions.

## Preview

Build `collector/NoseCalibration.csproj` in Release mode. Microsoft Edge WebView2 Runtime is required. The current installer source bundles a pinned, Microsoft-signed WebView2 bootstrapper and runs it only when the runtime is missing; see `docs/INSTALLER-BUILD.md`. `tools/package.ps1 -Preview` creates versioned previews under `work/packages`; keep each complete extracted package folder together. Existing `dist` and earlier `work/preview` builds may be older and are not automatically updated by packaging.

Recording begins only after consent and **Start session**. **Stop recording** or **Submit Test** ends recording. Only the focused assessment page is recorded: pointer, click, keyboard, scrolling, selection and answer metadata; final answers; and click-triggered page screenshots (750 ms throttle, 120-image cap). Other applications and browser tabs are outside the collector's capture scope.

Local sessions are stored under `%LOCALAPPDATA%/NoseCalibration/sessions`. `--verification` marks a developer test session separately so the ingestion validator rejects it as participant data.

## Optional sharing with an invitation

Once the organizer enables the service, complete a human practice session and open Results. Paste the organizer's invitation code and choose **Connect**. Connecting does not upload a recording. Read the sharing notice, select its separate consent checkbox, then choose **Encrypt and share**. Only completed human recordings are eligible; stopped, timed-out, verification and Codex sessions are excluded.

The code is held only in app memory and cleared on disconnect or exit. The recording is encrypted locally for the organizer before transmission. **Stored** confirms encrypted storage; **Received by organizer** confirms retrieval, not validation or proof of human origin. Retrying reuses the frozen encrypted recording. Codes are limited to seven days and three recordings. This flow is implemented but is not yet enabled or live-verified.

## Optional legacy GitHub sharing

On Results, the setup buttons open fixed GitHub pages. Finish each step on GitHub; the collector does not create repositories, install the App or invite people automatically.

1. **Create repository:** in your personal account, create `nose-calibration-submissions` and choose **Private**. Reuse this one repository for later recordings.
2. **Install app:** install **Nose Calibration**, choose **Only select repositories**, and select only `nose-calibration-submissions`. Do not choose **All repositories**. Check that the permissions are Contents read/write and Metadata read-only.
3. **Open my repositories:** open that repository, then **Settings > Collaborators > Add people**, and invite **Dhruvsa1** once. The organizer must accept. Add no other collaborators; they block sharing.

For each recording, just:

1. Choose **Sign in to GitHub** if needed. Enter only the code displayed by this collector at `github.com/login/device`, authorize Nose Calibration and check the displayed account. Never enter a code someone sends you.
2. Read the sharing notice, consent, then choose **Encrypt and share**. Wait for the result. If encrypted data is stored but organizer access is not confirmed, wait for acceptance and share again to verify; the app cannot see pending invitations and issues no final receipt until access is verified.

The organizer has standing **write access** to this inbox, including future shared sessions, until you remove them in repository settings. They can decrypt submitted recordings. Numeric session metrics may receive optional Codex advisory review; raw code, key presses and screenshots are not automatically sent to a model. **Sign out** clears the local token; it does not revoke the GitHub grant. To revoke it, use GitHub **Settings > Applications > Authorized GitHub Apps**; manage or uninstall the repository installation under **Installed GitHub Apps**. Removing the organizer, revoking the App grant and uninstalling the App are separate controls and do not erase copies already received.

## Packaging and participant guide

The application project explicitly includes its six web files, four brand images, public recipient key and public GitHub App identifiers. It ships no GitHub CLI, researcher credentials, Codex integration or recipient private key. `tools/prepare-dependencies.ps1` currently supplies the separate private administrator's pinned GitHub CLI dependency; it is not required by participants.

`tools/package.ps1 -Preview` creates a self-contained Windows x64 ZIP in a new timestamped `work/packages` folder. It checks the public key and GitHub App pins, includes the optional per-user `Install.ps1`, and emits file hashes, `package-source.json` (source revision, version, build/runtime identity and dirty-preview status), and a ZIP `.sha256` sidecar. Release mode requires committed clean source and finalized release wording; previews remain explicitly labeled. On a build machine, `python tools/build_installer.py <zip> --expected-sha256 <published-hash> --compiler <ISCC.exe>` verifies a private snapshot of that ZIP and compiles `tools/collector-setup.iss` into an unsigned per-user setup EXE with an `.exe.sha256` sidecar and `build-provenance.json`.

Participants use only the setup EXE the organizer gives them directly, for example `NoseCalibration-Setup-0.1.0-preview-win-x64.exe`. The organizer publishes its SHA-256 separately, for example in the study announcement; participants compare it before running and stop if it differs. A checksum shipped alongside an altered file is not proof of its origin. The setup wizard installs for the current Windows account without administrator access and adds a Start menu entry. If Microsoft Edge WebView2 Runtime is missing, a setup EXE built from current source asks before installing it from Microsoft (internet needed, no administrator access); if that step fails or is declined, Nose Calibration is not installed. Choosing **Finish** does not open the app or start recording; participants then open **Nose Calibration** from the Start menu. The primary flow requires no PowerShell or ZIP extraction. Uninstalling removes program files, not recordings.

The ZIP is a developer and fallback route only. Developers, or participants the organizer explicitly gives a ZIP, can extract the complete ZIP into a new folder and run the EXE. Optionally, right-click `Install.ps1` and choose **Run with PowerShell**. `Install.ps1` checks the complete file list, sizes and hashes before copying to a unique per-user directory, and checks copied bytes again. It rejects extra files and links, preserves previous installations, restores the prior shortcut on failure where possible, and leaves its result visible until Enter. It adds no elevation requirement, startup entry or recording-folder writes. Synthetic tests exercise both Windows PowerShell 5.1 and PowerShell 7; these do not replace a clean-machine installation walkthrough.

Run `python tools/verify_package.py <zip> --expected-sha256 <published-hash>` to independently inspect archive paths, manifest coverage and hashes, required files, public key/client pins, source identity and version consistency, and known credential/private-file patterns without executing the package. The file allowlist excludes private admin scripts, authentication CLIs, state and recording archives. Older previews without the source manifest are rejected and must be rebuilt. This is bounded integrity/content-policy verification, not code signing, a general malware scan or an upload test.

The illustrated `docs/Nose-Calibration-Setup.pdf` is a visually checked development-preview draft covering local practice and the invitation sharing flow, with legacy GitHub instructions in an optional appendix. Its generator is `tools/create_setup_guide.py`; screenshot assets under `docs/images` show synthetic test content. It and `docs/PACKAGE-README.txt` lead with the setup EXE; only the text guide's appendix covers the organizer-directed ZIP fallback. Update preview/release wording only after the pending release checks pass.

Legacy GitHub sharing stores each encrypted submission under `submissions/{sessionId}/submission.nose` in the participant-owned **private** inbox repository. Personal-account collaborators receive write access to that dedicated repository; this must be disclosed. Invitation sharing uses the separate study service and grants no GitHub access. No researcher credential, private recipient key, or Codex OAuth token belongs in this source tree or distribution. The collector has no Codex integration. Private admin ingestion and profile tooling remain in the private Nose project.

The empirical typing profile is integrated into private Nose's local practice mode and the separate private web Admin host. The Admin host has build and pure-policy test coverage.
